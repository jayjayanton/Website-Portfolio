The problem

What needed to be understood or built?

Preparing a renovation or extension means connecting information scattered across drawings, cadastral records, municipal planning documents and maps. A plan is more useful when its geometry, measurements and proposed changes can be reviewed together with the property it describes.

My contribution

The work I was responsible for.

I took PredioAI from product concept through deployment, including the responsive interface, backend services, geospatial integration, document inspection, measurement workflows, testing and delivery. I designed the interaction around user-selected elements and reviewable measurements, with property discovery and comparison supporting the plan workspace.

Approach

How I worked through the problem.

01

Connect public property data

Integrate municipal ArcGIS REST services for cadastral attributes, zoning and valuation information. Present searchable records and parcel layers in a React and Leaflet interface, with Python/FastAPI endpoints connecting the application to its data and analytical services.

02

Make drawing geometry interactive

Extract native text, vector paths and CAD entities using PyMuPDF and ezdxf, with supported DWG conversion workflows. Let users inspect a drawing, confirm units or calibrate a known length, select elements and calculate measurements with manual correction.

03

Place proposals in geographic context

Use Shapely and pyproj for geometry operations, spatial intersections and coordinate transformations. Support scaled figures and footprint placement on the parcel map, then compare proposals with reviewed municipal parameters, including available setback information.

04

Keep outputs usable beyond the screen

Link selections to measurements, organize property comparisons and export supported results as CSV, JSON or GeoJSON. Automated frontend and backend checks support production builds and deployment through GitHub Actions, with the frontend on GitHub Pages and the API on Render.

Result & scope

What the work delivered.

A deployed application brings parcel exploration, document inspection and spatial project preparation into one workflow. It demonstrates how public data services and analytical libraries can become an interactive product that users can inspect, correct and reuse.

Scope & next steps

  • The current plan workflow reads native PDF/CAD geometry and text. Targeted computer vision for scanned or image-based plans is a planned extension; automatic room recognition is not presented as an implemented capability.
  • Measurements depend on confirmed units or calibration and user review. Planning comparisons depend on the property information and municipal parameters supplied.
  • Outputs support project preparation and professional review; the case study does not claim automated permit approval, construction budgets or material estimates.

Learning & progression

How this work develops my practice.

The central design lesson is that trustworthy interaction depends on visible assumptions: confirmed scale, identifiable source geometry and reviewed municipal parameters. Connecting those assumptions to maps and measurements is as important as performing the underlying geometric calculation.
